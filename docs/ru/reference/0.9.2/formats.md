## `PROJECT_CONFIG_FILE`

Управляющая переменная CMake, не ключ YAML. **Тип:** путь; **default с 0.10.0:**
пустая строка (автовыбор).

Без явного пути ищутся только `stm32_config.yml`, `stm32_config.yaml` и
`stm32_config.toml` в корне проекта. Один файл — выбран; несколько — ошибка
`SCY-E016` со списком; ни одного — `SCY-E017`. Приоритетов между расширениями нет.
Добавление или удаление кандидата вызывает перенастройку при следующей сборке
(CMake `CONFIGURE_DEPENDS`); содержимое выбранного файла также отслеживается.

```powershell
cmake -S . -B build -DPROJECT_CONFIG_FILE=config/application.toml
```

Явный непустой путь обходит автовыбор, даже если в корне несколько кандидатов.
Относительный путь отсчитывается от корня проекта; абсолютный также допустим.
Отсутствующий явно выбранный файл — `SCY-E004`.

Найденное имя не записывается в кэш: при повторном Configure автовыбор выполняется
снова. Явный путь в кэше сохраняется по обычным правилам CMake. Для возврата:

```powershell
cmake -S . -B build -DPROJECT_CONFIG_FILE=
```

Либо удалите запись через `-UPROJECT_CONFIG_FILE` или очистите кэш.
**После обновления с 0.9.3:** старое значение кэша `stm32_config.yml` считается
явным выбором; для поиска `.yaml`/`.toml` его нужно сбросить. Обычная переменная,
заданная `set(PROJECT_CONFIG_FILE ...)` вызывающим CMakeLists, также уважается.

## YAML и TOML

Основной файл, каждое подключение и `profiles_file` определяют формат по своему
расширению: `.yml`/`.yaml` — YAML, `.toml` — TOML. Другие расширения, включая
`.json`, `.cfg` и верхний регистр, дают `SCY-E015`. Это изменение относительно
0.9.3, где yq мог прочитать файл с произвольным расширением.
Ошибка синтаксиса TOML — `SCY-E005` с диагностикой yq. Проверен Mike Farah yq 4.44.3.

```toml
include = "common.yml"
project_name = "telemetry"
mcu = "STM32F103C8T6"
sources = ["main.c"]
use_cmsis = false
use_hal = false

[profiles.Debug]
stack_size = "2K"
compile_definitions_append = ["TRACE=1"]
```

Форматы можно смешивать в одной цепочке подключений. Оба преобразуются в JSON
и используют одни правила [слияния](includes.md), профилей и overrides.
В TOML строки требуют кавычек; `[profiles.Debug]` соответствует вложенному объекту YAML.
В TOML нет `null`: пустая строка или массив имеют смысл по
[общим правилам](semantics.md#empty-values), а не являются универсальным аналогом null.
В частности, пустой массив `_append` не удаляет накопленные добавления профиля.

Внешний `profiles_file` может быть TOML; из него по-прежнему читается только
`profiles`, остальные ключи (включая `include`) игнорируются. Ограничения
уплощения, имён профилей, флагов и целочисленных размеров памяти сохраняются.
Смена формата сама по себе не включает CMSIS, HAL или иной backend.

**ТЗ:** 3.1.5, 3.8, TC-80/TC-81. **Проверки:** 19 сценариев `configure.formats-*`
в [манифесте](../../../../tests/cases.json): эквивалентные YAML/TOML, профили,
внешний list, смешанные цепочки, пустые значения, ошибочный формат и синтаксис,
автовыбор, явный выбор, кэш и перенастройка Ninja без компиляции прошивки.
