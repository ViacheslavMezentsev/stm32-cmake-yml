## Граница версии и контракта

Этот справочник фиксирует реализацию с версией 0.9.2 в коммите
`f8ef5200fc7a4a96d6f3fe9111afb8f8825474b0`. Это идентификатор проверенной
реализации, а не утверждение о наличии релизного тега. Дата аудита: 2026-09-22.
PR #3 добавил тесты, но не менял модули фреймворка. Исправления в локальном
коммите `858013a7f31a674a91149ea3a68a5200498d92cc` на момент аудита не слиты.
Одна строка версии не позволяет отличить эти состояния: проверяйте commit.

Карточка задаёт поддерживаемое назначение опции и наблюдаемое поведение базы.
Errata отдельно описывает отклонение от ожидаемого результата. Исправления не
переписывают историю 0.9.2. Для новой реализации обновляйте матрицу совместимости;
не объявляйте версию появления опции без подтверждённой истории.

## Чтение и приоритеты

Потребитель подключает `stm32_yml.cmake`, вызывает
`stm32_yml_prepare_project_data`, затем `project()` с полученными именем и языками,
затем `stm32_yml_setup_project`. Toolchain выбирается до `project()` самим проектом.
`yq` преобразует YAML в JSON, CMake 3.19+ разбирает его. Примеры карточек — фрагменты,
а не самостоятельные прошивки.

Порядок приоритетов: defaults → IOC → YAML → выбранный профиль →
`STM32_YML_OVERRIDE_*`. Фактически профиль и overrides применяются до IOC;
IOC заполняет оставшиеся неопределённые/пустые значения. Некоторые defaults
устанавливаются только в конкретном режиме или при включении функции, поэтому
единого универсального набора defaults нет. См. карточку каждой опции.

Ключ профиля заменяет значение; `<key>_append` дополняет список после замены.
Механизм не ограничен четырьмя именами списков и не проверяет типы. Не используйте
его для неоднозначных преобразований скаляров. Внешний файл — источник профилей,
а не обещание глубокого объединения нескольких конфигураций.

## Отсутствие, null, false, ноль и пустые списки

- Отсутствующий ключ не создаётся парсером. `key:` и `key: null` дают пустое значение.
- `false` и `0` сохраняются и не заменяются defaults только потому, что они ложные.
- `[]` превращается в пустой CMake-список. Для compile_definitions это очистка;
  для languages и cppcheck_args/ignores — выбор defaults. Поведение зависит от опции.
- `key: auto` имеет специальный смысл только там, где его обрабатывает потребитель.
- Пустой `STM32_YML_OVERRIDE_*` игнорируется и не служит командой очистки.

Простые MCU-имена, пути и размеры пишите без кавычек: `mcu: STM32F103C8T6`,
`heap_size: 1K`. Кавычки нужны при значимом для YAML синтаксисе или для сохранения
строки вместо boolean/number. Они не отменяют последующую нормализацию CMake.

## Типы, имена и валидация

Типы карточек — рекомендуемый контракт входа, не JSON Schema, уже enforced кодом.
В базе нет общей проверки неизвестных ключей или enum. Незнакомый ключ может
быть экспортирован и затем проигнорирован; успешный Configure не выявляет все опечатки.
`arduino.core_path` в карточке означает вложенную YAML-секцию `arduino:`, а не
буквальное имя ключа с точкой. Вложенные объекты уплощаются через `_`; запись
`arduino: {core_path: ...}` становится `arduino_core_path`. Не создавайте коллизии
между вложенными и плоскими ключами. Рекомендуются списки простых значений.

Профили именуйте буквами/цифрами. `_` ломает list в базе (E005), а regex-символы
могут менять выбор из-за необработанного регулярного выражения имени.
Строки флагов разбиваются по пробелам и затем становятся CMake-списками.
Не обещается произвольный shell quoting, экранирование пробелов или семиколонов.

## Пути и стадии

Большинство собственных файлов фреймворка задаются относительными путями от
корня проекта; sources — от текущего source directory; include_directories
следует правилам CMake. Путь относительно YAML-файла автоматически не вводится.
Configure/Generate создаёт граф, `.ld` и команды. Компиляция, линковка, objcopy,
Cppcheck и CRC выполняются позднее. Clock tree из IOC, настройка периферии и
аппаратная корректность этими конфигурационными тестами не подтверждаются.

## Кэш и внешние управляющие параметры

| Параметр (не YAML-опция) | Контракт |
| --- | --- |
| `PROJECT_CONFIG_FILE` | CACHE STRING, default `stm32_config.yml`; путь от корня |
| `STM32_YML_PROFILE` | CACHE STRING, пусто = база; `list` печатает список и завершает Configure ошибкой |
| `STM32_YML_OVERRIDE_<param>` | CACHE STRING, непустой скаляр поверх профиля; вложенный параметр использует `_` |
| `CMAKE_USER_HOME` | Переменная окружения для каталога STM32Cube/Repository |
| `CMAKE_TOOLCHAIN_FILE`, `STM32_TOOLCHAIN_PATH` | Входы проекта/toolchain, не YAML-параметры фреймворка |
| `MCU`, `HEAP_SIZE`, `STACK_SIZE` | Производные cache entries; в базе сохраняют старые значения (E001) |
| `ARDUINO_CORE_DIR`, `MCU_TARGET`, `USE_CORE_MAIN` | Выходы для Arduino-обёрток; поведение при пропуске см. карточки |

Отсутствие `-D` в следующей команде не удаляет запись кэша. Для удаления используйте
`-USTM32_YML_OVERRIDE_stack_size`, для сброса профиля — `-DSTM32_YML_PROFILE=`.
Для исходной 0.9.2 при смене MCU/размеров используйте свежую build-папку (E001).
Даже с исправлениями смена toolchain требует отдельного build directory.

## Совместимость и доказательства

Автоматические тесты покрывают конкретные сценарии и не доказывают весь текст
карточки. Их перечень находится в [машиночитаемом индексе](../../../reference-index.json).
Отсутствие теста означает отсутствие автоматического покрытия, а не известную ошибку.
Errata содержит способы подтверждения отдельно. Целевые имена, семейства MCU и
версии библиотек определяются также закреплёнными внешними зависимостями;
справочник не обещает поддержку любых сочетаний Cube, Arduino и stm32-cmake.
