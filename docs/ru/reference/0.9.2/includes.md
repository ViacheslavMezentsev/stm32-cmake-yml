## `include`

`CFG-INCLUDE` · **Тип:** путь или список путей · **Default:** нет подключений

**С версии 0.10.0 (пока не выпущена).** В этой ветке реализованы подключения YAML.
Поддержка TOML и автоматический выбор имени файла — следующие части этапа 4.
В 0.9.2/0.9.3 ключ не подключает файлы.

```yaml
include:
  - config/common.yml
  - config/board.yml
project_name: telemetry
compile_definitions_append:
  - TELEMETRY=1
profiles:
  Debug:
    compile_definitions_append:
      - TRACE=1
```

Пути `include` разрешаются относительно файла, в котором они записаны.
Остальные пути проекта (`sources`, `linker_script`, `profiles_file` и т. п.)
сохраняют прежнюю базу — корень проекта; каталог фрагмента не становится новой базой.
Подключённый файл может подключать другие файлы. Сначала обрабатываются его
подключения, затем он сам. Соседние файлы применяются в порядке списка,
основной файл — последним. Повторное подключение вне текущей цепочки допустимо
и повторяет операции, в том числе добавление элементов; дубликаты не удаляются.

Правила слияния до уплощения в переменные CMake:

- Объекты сливаются рекурсивно; профили объединяются по точному имени.
- Скаляры и списки заменяются. `null` сбрасывает унаследованное значение.
- `<ключ>_append` вне `profiles` добавляет элементы к списку `<ключ>`.
  В пределах одного файла замены выполняются перед добавлениями независимо
  от порядка записи ключей. Суффикс `_append` зарезервирован и для пользовательских ключей.
  Добавление принимает массив; `null` и пустая строка ничего не добавляют.
  База — массив, отсутствующее значение, `null` или пустая строка; иной тип — `SCY-E013`.
- Внутри профиля списки `_append` накапливаются между файлами и применяются
  только при активации профиля. Замена обычного списка профиля не удаляет
  накопленный `_append`; чтобы сбросить его, задайте `_append: null`.
  Пустой массив не удаляет накопленные добавления.

Отсутствующий `include`, `null`, пустая строка и `[]` означают отсутствие подключений.
Каждый элемент непустого списка — непустая строка. Неверный тип — `SCY-E012`,
отсутствующий файл — `SCY-E010`, цикл — `SCY-E011`; последние два сообщения
содержат цепочку файлов. Корень каждого файла должен быть одним YAML-объектом
(`SCY-E014`). Все прочитанные файлы входят в зависимости Configure.

### Что содержит effective.json

`build/stm32_config.effective.json` — дерево после слияния файлов, **до** выбора
профиля, overrides, чтения IOC и подстановки defaults. JSON сохраняет типы,
`null`, пустые массивы и все встроенные профили. Верхний служебный ключ `include`
удалён; это не полный отчёт о конечных флагах цели.
Файл перезаписывается при Configure; при ошибке загрузки старый файл удаляется.

`profiles_file` остаётся отдельным механизмом: читается только его `profiles`,
включая прежние правила замены встроенных профилей. Его `include` игнорируется,
внешние профили не попадают в effective.json. См. [профили](profiles.md).

**Контракт:** ТЗ 3.8; ограничения [уплощения и значений](semantics.md) сохраняются.
**Реализация:** [модуль include](../../../../cmake/stm32_yml_include.cmake).
**Проверки:** 16 сценариев `configure.include-*` в [манифесте](../../../../tests/cases.json):
слияние и порядок, профили и override, null, повторные подключения, замена/добавление,
внешние профили, зависимости Configure, повторная настройка и ошибки.
Смешанные форматы пока не проверяются; TC-80 реализован частично.
