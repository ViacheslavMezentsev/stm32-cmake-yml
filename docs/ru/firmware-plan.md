# План групп прошивочных тестов

[Документация](index.md) · [English](../en/firmware-plan.md) · [Контракт исполнения](firmware-testing.md)

Цель — проверить все варианты использования, для которых можно задать наблюдаемый
контракт на выбранной модели. 115 Configure-сценариев не равны 115 прошивкам:
среди них есть ошибки YAML, повторная конфигурация и синтетические библиотеки.
Их не нужно превращать в исполняемые тесты. Каждая новая группа получает свою ветку.

| Группа | Что проверяем | Отправная точка и граница |
| --- | --- | --- |
| 1. Базовый запуск | Startup, .data/.bss, C++-конструктор, метаданные, CRC, выход и зависание | Адаптация F1 `02-semihosting`: 18 сборок, 24 QEMU + 24 Renode. Слито в main (`493771d`). |
| 2. Режимы сборки | Bare metal без CMSIS/HAL со своим startup; CMSIS без HAL; явный и шаблонный linker script; профили одного MCU | Слито в main `ba9bde7`: четыре новых профиля, свой bare startup и общие проверки исполнения. Всего 42 сборки и 48 проверок в каждом симуляторе. Новая настройка тактирования/периферии не добавляется. |
| 3. Библиотеки и окружение C/C++ | Свои CMake-модули, ETL, разделение языковых флагов; затем Arduino и RTOS отдельными подэтапами | Слито в main `a53f809`: C/C++-библиотека и ETL vector/string без I/O; всего 54 сборки / 120 проверок симуляторов. E008 описано с обходом и регрессией; Arduino startup и RTOS tick требуют своих контрактов. External FreeRTOS/E007 остаётся регрессией и errata без исправления. |
| 4. Ядра и ABI | M0, M3, M4/FPU, M7; startup, доступные инструкции и soft/hard-float | Отдельно проверять F0, F1, F3/F4/G4, F7. netduino2/netduinoplus2 подходят лишь при подтверждённом наборе инструкций и карте памяти; запуск на более старшем ядре не доказывает совместимость с младшим. Для остальных — подходящая модель Renode. |
| 5. Периферия | GPIO, SysTick/таймеры, UART; затем отдельные протоколы | Начать с `03-blink` на HSI без PLL, проверять события GPIO и виртуальное время. Нужны работающие модели регистров/IRQ; memory-заглушки не подтверждают периферию. Внешние устройства и электрические свойства — аппаратные тесты. |

Кандидаты находятся в [demo-stm32-cmake](https://github.com/ViacheslavMezentsev/demo-stm32-cmake),
в первую очередь в stm32f1xx и stm32f4xx. Указание примера означает очередь анализа,
а не подтверждённую совместимость его текущего содержимого с симулятором.
Локальные исходные проекты используются только для чтения.

## Как включать новый сценарий

1. Проверить CPU/ISA/FPU, VMA/LMA, reset/векторы и обращения к устройствам до main.
2. Назначить статус: build-only, runnable на конкретной модели или blocked с причиной.
   Отсутствие модели не считается пройденным тестом.
3. Собрать на опорной паре GCC 14.2 / CMake 3.28; сверить ELF/BIN и ожидаемый вывод.
4. Добавить отрицательную проверку, специфичную контракту, и предел времени.
5. Расширить на закреплённые шесть пар инструментов и подходящие симуляторы.
   Сохранять команды, версии, метаданные и причины исключений.

Сначала покрываем разные механизмы сборки на одном MCU, затем расширяем ядра.
Совместимость оценивается для прошивки и её пути исполнения, а не для названия
семейства целиком. Частичная модель должна быть явно названа в отчёте.
Перед новой группой учитываем уточнения автора; уже выбранную semihosting-прошивку
можно переносить между симуляторами без повторного выбора исходного примера.

Arduino String со своим main реализован в `codex/firmware-arduino-string`: всего 60 сборок / 132 проверки симуляторов. Полный Arduino startup и RTOS остаются отдельными этапами.
