# Переход с 0.9.x на 0.10.0

[Документация](index.md) → Переход · [English](../en/migration-0.10.md)

Руководство описывает переход на 0.10.0. Статус подготовки и публикации —
в [дорожной карте](../../TODO.md). Полный перечень изменений —
в [CHANGELOG](../../CHANGELOG.md), требования совместимости — п. 7.9
[ТЗ](../TECHNICAL_SPECIFICATION.md).

## Порядок перехода

1. Сохраните рабочую версию проекта и закреплённые версии зависимостей.
   Если исходная версия — 0.9.2, прочитайте также изменения 0.9.3 и
   [errata](errata/index.md): исправления между ними входят в переход.
2. Проверьте `cmake --version`: требуется **CMake ≥ 3.21**. Проверьте также
   выбранный CMake в VS Code и контейнере CI. Матрица проекта проверяет 3.21.7
   и 3.28.3; менять компилятор только ради перехода не требуется.
3. Начните с нового каталога сборки, например `build/migration-010`.
   «Удаление кэша и перенастройка» в VS Code не удаляет все старые каталоги
   библиотек и артефакты. Старый каталог можно сохранить для сравнения.
4. Проверьте выбор файла конфигурации и профиля, затем выполните Configure/Generate.
5. Сверьте пути артефактов и потребляющие их команды: VS Code, прошивальщик,
   отладчик, CI, архивирование. После этого соберите проект и проверьте прошивку.
6. Сопоставьте сообщения по кодам, а при ошибке приложите JSONL из каталога сборки.
   Успех Configure сам по себе не подтверждает сборку или работу устройства.

Версию `stm32_cmake_yml_version` в конфигурации обновляйте вместе с фактической
версией подключённого фреймворка, после выпуска. Не меняйте её заранее только
ради подавления сообщения о несовпадении.

## Файл конфигурации и кэш

Прежний `stm32_config.yml` можно оставить. Без явного `PROJECT_CONFIG_FILE`
фреймворк ищет единственный файл `stm32_config.yml`, `stm32_config.yaml` или
`stm32_config.toml` в корне проекта. Несколько кандидатов дают `SCY-E016`,
отсутствие — `SCY-E017`. Допустимы только расширения `.yml`, `.yaml`, `.toml`
в нижнем регистре; другое расширение даёт `SCY-E015`.

Старый кэш может содержать явный `PROJECT_CONFIG_FILE=stm32_config.yml`.
В новом каталоге его нет; при повторной настройке удалить запись можно через
`-UPROJECT_CONFIG_FILE`, а пустое `-DPROJECT_CONFIG_FILE=` возвращает автовыбор.
Если переменную снова задаёт пресет или CMakeLists, действует это значение.
Явный путь обходит автовыбор; относительный путь отсчитывается от корня проекта.
См. [форматы](reference/0.9.2/formats.md).

`include` и суффикс `_append` вне профилей теперь служебные. Если проект использовал
их как собственные ключи без такого смысла, переименуйте их. TOML и разбиение на
файлы необязательны. `stm32_config.effective.json` показывает результат слияния
**до** профиля, overrides, IOC и defaults; это не итоговые свойства CMake-цели.
См. [правила слияния](reference/0.9.2/includes.md).

## Каталоги сборки и артефакты

Таблица показывает типовые пути относительно каталога сборки. Пути с
`<…>` обозначают шаблон, а не буквальное имя.

| Случай | 0.9.x | 0.10.0 |
| --- | --- | --- |
| Внешний каталог `sources` | `external_<sanitized-path>` | `_deps/<path>` без начальных `..`, например `_deps/modules/etl` |
| Обёртка Arduino Core | `arduino_core` | Путь обёртки относительно корня проекта, например `Arduino/Core` |
| Библиотека Arduino | `arduino_lib_<name>` | Путь подключаемого каталога; для внешнего — под `_deps` |
| Собственная Arduino-библиотека | `arduino_custom_<sanitized-path>` | Путь относительно проекта, например `Arduino/libraries/Wire` |
| Обычная корневая цель `app`, Ninja, без настройки имён | `app.elf`, `app.bin`, `app.hex`, `app.lss`, `app.map` | Те же имена |
| `OUTPUT_NAME`, `OUTPUT_NAME_<CONFIG>`, `<CONFIG>_POSTFIX` | В частности, `lss`/`map` сохраняли имя цели | Все запрошенные артефакты используют итоговое базовое имя ELF |
| `RUNTIME_OUTPUT_DIRECTORY`, цель в подкаталоге, Multi-Config | Расположение отдельных артефактов могло отличаться от ELF | `bin`, `hex`, `srec`, `lss`, `map` рядом с ELF, с учётом конфигурации |

При коллизии каталогов добавляется суффикс `-<4 символа SHA1>`.
Внутренний путь `_deps/…` при наличии внешних зависимостей может вызвать
`SCY-E302`; переименуйте такой каталог проекта. Старые каталоги автоматически
не очищаются. Не привязывайте пользовательские команды к внутренним путям `.o`.

В собственных CMake-командах путь к HEX цели `app` можно выразить так:

```cmake
"$<TARGET_FILE_DIR:app>/$<TARGET_FILE_BASE_NAME:app>.hex"
```

Если внешнему инструменту временно нужен прежний фиксированный путь MAP,
после настройки цели добавьте копирование (артефакт `map` должен быть включён):

```cmake
add_custom_command(TARGET app POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        "$<TARGET_FILE_DIR:app>/$<TARGET_FILE_BASE_NAME:app>.map"
        "${CMAKE_BINARY_DIR}/app.map"
    VERBATIM)
```

Добавляйте команду в том же CMake-каталоге, где создана цель. Для параллельных
конфигураций используйте разные пути копий, чтобы Debug и Release не перезаписывали их.

## Диагностика и Arduino

Тексты сообщений локализованы. Для автоматизации используйте код сообщения и
код завершения процесса вместо поиска русской фразы или старого `[CRC ERROR]`.
`-DSTM32_YML_MESSAGE_CODES=ON` показывает коды в консоли, `-DSTM32_YML_LANG=ru`
или `en` фиксирует язык. `stm32_yml_messages.jsonl` содержит сообщения Configure,
`stm32_yml_build_messages.jsonl` — сообщения скрипта CRC при сборке, включая
`SCY-E708` при ошибке обработки. Это не журнал всех сообщений компилятора.
См. [каталог сообщений](reference/0.9.2/messages.md).

Arduino по умолчанию остаётся в режиме `wrappers`. Переходить на `native`
необязательно. Цели `Arduino::Options` и `Arduino::Platform` позволяют обёрткам
получать общие параметры и параметры платы; удаляйте собственные флаги только
после проверки того, что обёртка действительно использует эти цели.
В `native` другой способ подключения библиотек, а `core_cmake_dir` и
`mcu_target` не используются. При `use_core_main: false` ответственность за
начальную инициализацию остаётся у приложения. Подробности и примеры —
в [руководстве Arduino](arduino.md).

## Что остаётся прежним и что проверено

Имена профилей по-прежнему не содержат `_`; размеры памяти — целые числа
с допустимыми суффиксами `K`/`M`, без `1.5K`. В bare metal без CMSIS разработчик
сам подключает startup, таблицу векторов и необходимые флаги.

[Пресеты](presets.md) показываются совместно с YAML и CMakeLists: пресет выбирает
окружение и профиль, YAML описывает конфигурацию, CMake подключает цели.
Генерации пресетов нет. [JSON Schema](schema.md) — дополнительная проверка L1,
не часть Configure; разрешённые собственные ключи означают, что схема не выявляет
любую опечатку и не подтверждает наличие зависимостей.

На завершении этапа 4 (`e5d93c6`) пройдены все локальные уровни L0–L5:
1452 Configure, 618 сборок, 336 запусков QEMU и 612 Renode; Firmware на том же
коммите также прошёл. Это проверка конкретной матрицы, не всех пользовательских
прошивок и периферии. Arduino `native` входит в сборки, но пока не в запуски
эмуляторов из-за ограничений RCC/PWR. См. [методику](firmware-testing.md) и
[ограничения эмуляции](emulation.md). Перед выпуском проверки повторяются
на итоговом коммите версии.

## Обновление с 0.10.0 до 0.10.1

Обновите сам модуль до тега `v0.10.1`, затем укажите
`stm32_cmake_yml_version: 0.10.1` и выполните чистое конфигурирование.
Версия в YAML не переключает подключённый код. Формат конфигурации сохраняется;
`crc_method` можно не указывать (`auto`). Схема размещения секций автоматически
не меняется. Подробности: [описание выпуска](../releases/v0.10.1.md),
[метод CRC](crc-methods.md) и [ограничение E010](errata/E010.md).

## Обновление с 0.10.1 до 0.10.2

Подключите модуль `v0.10.2`, обновите `stm32_cmake_yml_version` до `0.10.2`
и выполните чистое конфигурирование. YAML и TOML сохраняют прежние приоритеты.
Абсолютные `sources`, включая другой диск Windows, теперь разрешаются корректно;
менять существующие относительные пути не требуется. При разборе текста отчёта
замените ожидание `[yml]` на `[cfg]`; коды сообщений и имена переменных не меняются.
[TOML/include/Presets](presets.md) — дополнительный пример, переход на TOML необязателен.
[Заметки к выпуску](../releases/v0.10.2.md); публикация ещё впереди.
