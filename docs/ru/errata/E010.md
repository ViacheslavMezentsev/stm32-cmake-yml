# E010 — Абсолютный sources на другом диске Windows

[Errata](index.md) · [English](../../en/errata/E010.md)

**Статус:** fixed в main (`8624bae`); для 0.10.2, не выпущено.
**База:** 0.10.0 и main `6d066f0`. **Подтверждение:** reproduced, Windows,
CMake 3.21.7 / xPack GCC 14.2.1-1.1. Опция: `sources`.

Абсолютный каталог `C:/...` при проекте на D: превращается внутри обработки
sources в `<проект>/C:/...`. Каталог не подключается; Configure продолжается
с SCY-W302, а его исходник отсутствует в compile_commands.json.
Это ограничение версий до 0.10.1 включительно. Исправление использует такое же
разрешение абсолютных/относительных путей, как предварительный план каталогов.

TC-95: четыре сценария sources-absolute-* проверяют файлы, каталоги с пробелами,
пропущенный файл, каталог без CMakeLists.txt и подмену CMSIS startup/system.
Относительные варианты продолжают проверяться прежними сценариями.
TC-44: Windows baremetal-empty-list требует extra.c из каталога и отдельный
single file.c с другого диска в compile_commands.json, отсутствие W302 и
успешную сборку. Только успешный набор Configure/Build + Host выставляет
в summary.json tc44_complete=true. Пользовательские проекты не меняются.
Локальный нативный TC-44 и GitHub Firmware на `8624bae` прошли
([run 37133257759](https://github.com/ViacheslavMezentsev/stm32-cmake-yml/actions/runs/37133257759)).

Обход для 0.10.1 и ранее: разместить модуль на том же диске и задать поддерживаемый относительный
путь; автоматическое перемещение модулей не выполняется. ТЗ 4.6.1, 8.5.7, TC-44.
