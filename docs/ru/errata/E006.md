# E006: Ошибка CRC может завершаться успехом и заглушкой

[Документация](../index.md) → [Errata](index.md) → E006 · [English](../../en/errata/E006.md)

**Статус:** Исправлено в 0.9.3 (`4cd3404`). **Baseline:** `0.9.2 @ f8ef5200fc7a4a96d6f3fe9111afb8f8825474b0`.

[`crc_enable`](../reference/0.9.2/postbuild.md#crc-enable), [`flash_size`](../reference/0.9.2/postbuild.md#flash-size)

## Воспроизведение

Вызвать python scripts/stm32_crc.py missing.bin crc.bin при отсутствующем missing.bin.

## Ожидание и фактическое поведение

Для контроля целостности ожидается достоверный CRC либо явный провал шага. Фактически graceful_exit печатает CRC WARNING, записывает 00000000 и возвращает 0. Такое поведение намеренно заложено кодом и ограничивает смысл зелёной сборки; не каждый последующий objcopy обязательно завершится успешно.

## Обход для 0.9.2 и совместимость

В проверяемых сборках считать CRC WARNING ошибкой и независимо проверять рассчитанную секцию. Не считать любое нулевое CRC доказательством ошибки: ноль возможен как корректный результат.

## Подтверждение и исправление

Воспроизведён вызов с отсутствующим файлом: exit 0, CRC WARNING, четыре нулевых байта. Полная прошивка при этом не собиралась.

[Source](https://github.com/ViacheslavMezentsev/stm32-cmake-yml/blob/f8ef5200fc7a4a96d6f3fe9111afb8f8825474b0/scripts/stm32_crc.py).

Исправление: `4cd34042d182ebae49e8acf886c6594adc3c9139` (ТЗ 4.15.7, 4.15.9). Любой сбой расчёта выводит `[CRC ERROR]` и завершает шаг ненулевым кодом; заглушка не пишется. Образ строится из секций ELF в регионе `FLASH`, поэтому секции вне Flash больше не раздувают его: на `STM32H503CB` секция в резервной SRAM давала образ 896 МиБ и заглушку. Регрессии: `tests/test_firmware_crc_script.py`, `configure.crc-flash-region-missing`. Слито в [PR #41](https://github.com/ViacheslavMezentsev/stm32-cmake-yml/pull/41) (merge `29e64a4`), выпуск 0.9.3.
