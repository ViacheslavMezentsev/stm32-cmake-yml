# E009 — Кодировка Python-диагностики CRC/BIN

[Errata](index.md) · [English](../../en/errata/E009.md)

**Статус:** merged, целевой выпуск 0.10.1; не выпущено.
**База воспроизведения:** 0.10.0, `02b335e`; исправление слито в main, коммит `d759e48`.
**Подтверждение:** reproduced. Опции: `crc_enable`, `build_artifacts`;
язык задаётся `STM32_YML_LANG`, а скрипту передаётся каталог через `--messages`.

Python использовал кодировку stdout/stderr окружения. При CP1251/CP866 и
декодировании как UTF-8 русские сообщения и пути искажались; вычисление CRC
могло завершиться успешно. JSONL уже записывался в UTF-8.

Регрессия: `python -m unittest discover -s tests -p test_crc_encoding.py`.
Она принудительно задаёт кодовые страницы дочернему процессу, проверяет байты
pipe/file, CRC/BIN, ошибки, JSONL и CMake/Ninja POST_BUILD. На старом коде
воспроизведён UnicodeDecodeError, после исправления тесты проходят.

Исправление: CLI настраивает существующие stdout/stderr через reconfigure;
импорт не меняет потоки. ТЗ 4.16.15, TC-88. Временный обход для старой версии —
PYTHONIOENCODING=utf-8 в окружении запуска Python; декодер IDE должен читать UTF-8.
Интерактивная консоль и все настройки IDE этим тестом не проверены.
