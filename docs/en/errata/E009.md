# E009 — Python CRC/BIN diagnostic encoding

[Errata](index.md) · [Русский](../../ru/errata/E009.md)

**Status:** released — fixed in [0.10.1](https://github.com/ViacheslavMezentsev/stm32-cmake-yml/releases/tag/v0.10.1).
**Reproduced base:** 0.10.0, `02b335e`; fix merged into main, commit `d759e48`.
**Evidence:** reproduced. Options: `crc_enable`, `build_artifacts`;
STM32_YML_LANG selects the catalog passed to the script using --messages.

Python used the environment's stdout/stderr encoding. CP1251/CP866 output
read as UTF-8 corrupted Russian messages and paths even when CRC calculation
succeeded. JSONL was already UTF-8.

Regression: `python -m unittest discover -s tests -p test_crc_encoding.py`.
It forces child code pages and checks pipe/file bytes, CRC/BIN, errors, JSONL
and CMake/Ninja POST_BUILD. The old code reproduced UnicodeDecodeError;
the fixed code passes.

The CLI reconfigures existing stdout/stderr; import leaves streams untouched.
Spec 4.16.15, TC-88. Temporary workaround for old versions: set
PYTHONIOENCODING=utf-8 for Python and use a UTF-8 IDE decoder. These tests do
not validate interactive consoles or every IDE configuration.
