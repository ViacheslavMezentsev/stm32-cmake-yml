# E008: profile-only dynamic language settings are not exported

[Errata](index.md) · [Русский](../../ru/errata/E008.md)

**Status:** Fix prepared: `d8708b4`, branch `claude/release-0.9.3`; not merged, no release. Reproduced on version 0.9.2,
main `ba9bde7`, with the stm32-cmake backend and a fresh configure directory.

When `compile_options_c`, `compile_options_cxx`, `compile_definitions_c` or
`compile_definitions_cxx` exists only inside a profile, the application log says
it was applied but the executable compilation commands omit its value.
Expected behavior is the same language-specific application as for a root key.
This is not a stale-cache effect.

`stm32_yml_apply_profile` exports the selected value into
`stm32_yml_prepare_project_data`. The latter exports explicitly listed settings
and entries of `YAML_PARSED_KEYS`. The four language-specific keys are not on the
explicit list; a profile-only key appears there under `profiles_<name>_<key>`,
not its unprefixed name. Thus its value does not reach the caller.

**Workaround for 0.9.2:** declare these keys at the root (empty lists suffice), then set
values in profiles. This has been verified by the library firmware profiles:

```yaml
compile_options_c: []
compile_options_cxx: []
compile_definitions_c: []
compile_definitions_cxx: []
profiles:
  Lib:
    compile_options_c: [Wstrict-prototypes]
    compile_options_cxx: [fno-exceptions, fno-rtti]
    compile_definitions_c: [ONLY_C=1]
    compile_definitions_cxx: [ONLY_CXX=1]
```

Before the fix, `ci/build_firmware_smoke.py` configured a copy without the root
declarations and required the known omission (`profile_only_regression`).

Fix: `d8708b49e1734d7495d8c84cfe039515932a01e4` (spec 3.4.9). `stm32_yml_apply_profile` passes the keys set by the
profile and overrides (`STM32_YML_PROFILE_KEYS`), and
`stm32_yml_prepare_project_data` exports them like `YAML_PARSED_KEYS`, including
project-specific keys. The workaround is no longer needed: it is removed from the
test firmware, the known-failure probe is removed, and the `cmsisLibrary` and
`cmsisEtl` profiles build and run without root declarations (spec 7.5).
Regression: `configure.profile-only-keys` (TC-51). Merge and release are not confirmed.
