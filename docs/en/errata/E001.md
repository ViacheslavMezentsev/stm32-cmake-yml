# E001: Derived values remain stale in cache

[Documentation](../index.md) → [Errata](index.md) → E001 · [Русский](../../ru/errata/E001.md)

**Status:** Fix prepared, not merged. **Baseline:** `0.9.2 @ f8ef5200fc7a4a96d6f3fe9111afb8f8825474b0`.

[`mcu`](../reference/0.9.2/project.md#mcu), [`heap_size`](../reference/0.9.2/linker.md#heap-size), [`stack_size`](../reference/0.9.2/linker.md#stack-size)

## Reproduction

Change the MCU or heap/stack profile and configure again in the same build tree.

## Expected and actual behavior

Expected: new MCU/define and new .ld values. Actual: set(... CACHE ...) without FORCE preserves initial MCU, HEAP_SIZE and STACK_SIZE.

## Workaround and compatibility

Use a separate fresh build tree per profile. After the fix use STM32_YML_OVERRIDE_*; direct -DMCU/-DHEAP_SIZE/-DSTACK_SIZE no longer take precedence.

## Evidence and fix

Reproduced in configuration tests. Prepared fix branch: configure.reconfigure-memory and configure.reconfigure-mcu; they are not in this documentation branch test manifest.
