# E010 — Absolute sources directory on another Windows drive

[Errata](index.md) · [Русский](../../ru/errata/E010.md)

**Status:** fixed in main (`8624bae`); intended for 0.10.2, not released.
**Base:** 0.10.0 and main `6d066f0`. **Evidence:** reproduced on Windows,
CMake 3.21.7 / xPack GCC 14.2.1-1.1. Option: `sources`.

An absolute C:/... directory with a project on D: becomes <project>/C:/...
in source processing. Configure continues with SCY-W302 and the module source
is absent from compile_commands.json. This affects versions up to and including 0.10.1. The fix resolves paths using
the same rule as the preliminary build-directory plan.

TC-95: four sources-absolute-* cases cover files, directories with spaces,
missing files, directories without CMakeLists.txt and CMSIS startup/system
replacement. Existing cases retain relative-path coverage.
TC-44: Windows baremetal-empty-list requires extra.c from a directory and a
separate single file.c on another drive in compile_commands.json, no W302,
and a successful build. Only a passing Configure/Build + Host suite sets
tc44_complete=true in summary.json. User projects are not modified.
Native local TC-44 and GitHub Firmware passed on `8624bae`
([run 37133257759](https://github.com/ViacheslavMezentsev/stm32-cmake-yml/actions/runs/37133257759)).

Workaround for 0.10.1 and earlier: place the module on the same drive and use a supported relative path.
No modules are moved automatically. Spec 4.6.1, 8.5.7, TC-44.
