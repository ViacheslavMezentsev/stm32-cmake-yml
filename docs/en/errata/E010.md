# E010 — Absolute sources directory on another Windows drive

[Errata](index.md) · [Русский](../../ru/errata/E010.md)

**Status:** open; owner deferred the fix beyond 0.10.1.
**Base:** 0.10.0 and main `6d066f0`. **Evidence:** reproduced on Windows,
CMake 3.21.7 / xPack GCC 14.2.1-1.1. Option: `sources`.

An absolute C:/... directory with a project on D: becomes <project>/C:/...
in source processing. Configure continues with SCY-W302 and the module source
is absent from compile_commands.json. The reference describes relative sources;
TC-44's other-drive check is broader than the verified support. Do not report
this as a supported configuration or silently fix it in the test job.

Regression: the Windows variant of baremetal-empty-list in tests/cases.json.
ci/run_windows_checks.py requires different drives, exact W302 and missing extra.c.
Only temporary fixtures are used. A green job confirms the known limitation,
not a fix: summary.json has tc44_complete=false, known_limitations=[E010].

Workaround: place the module on the same drive and use a supported relative path.
No modules are moved automatically. Spec 4.6.1, 8.5.7, TC-44.
