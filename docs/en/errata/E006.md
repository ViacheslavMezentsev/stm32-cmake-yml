# E006: CRC failure can exit successfully with a stub

[Documentation](../index.md) → [Errata](index.md) → E006 · [Русский](../../ru/errata/E006.md)

**Status:** Open. **Baseline:** `0.9.2 @ f8ef5200fc7a4a96d6f3fe9111afb8f8825474b0`.

[`crc_enable`](../reference/0.9.2/postbuild.md#crc-enable), [`flash_size`](../reference/0.9.2/postbuild.md#flash-size)

## Reproduction

Run python scripts/stm32_crc.py missing.bin crc.bin with missing.bin absent.

## Expected and actual behavior

Integrity validation needs a valid CRC or explicit step failure. Actual graceful_exit prints CRC WARNING, writes 00000000 and returns 0. This is intentional code behavior limiting what a green build proves; a later objcopy is not guaranteed to succeed.

## Workaround and compatibility

Treat CRC WARNING as failure in validated builds and independently verify the computed section. Do not treat every zero CRC as proof of failure: zero can be a valid result.

## Evidence and fix

Missing-input invocation reproduced: exit 0, CRC WARNING, four zero bytes. No complete firmware was built.
