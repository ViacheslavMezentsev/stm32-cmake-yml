# История изменений

**Русский** · [English](CHANGELOG.en.md) · [README](README.md)

Все заметные изменения проекта записываются в этот файл. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют
[семантическому версионированию](https://semver.org/lang/ru/). Коды `E001`…`E008` —
записи [errata](docs/ru/errata/index.md); пункты ТЗ — разделы
[технического задания](docs/TECHNICAL_SPECIFICATION.md).

## [Не выпущено]

### Добавлено

- **Коды и язык сообщений** (ТЗ 4.16.5–4.16.10). Сообщения выводятся по постоянным
  кодам `SCY-<I|W|E><номер>` из каталога `cmake/stm32_yml_messages_catalog.cmake` на
  русском или английском. Язык задаёт `STM32_YML_LANG` (`auto`, `ru`, `en`); при `auto`
  он берётся из локали, на Windows — из реестра. `STM32_YML_MESSAGE_CODES=ON` показывает
  коды в выводе. Каждое сообщение Configure записывается в `stm32_yml_messages.jsonl`
  в каталоге сборки. Скрипт CRC при сборке выводит сообщения на языке Configure и
  записывает их в `stm32_yml_build_messages.jsonl`. Перечень кодов — в справочнике
  ([коды сообщений](docs/ru/reference/0.9.2/messages.md)); форма Issue просит приложить
  файл сообщений.

- **Версии компонентов** (ТЗ 4.2.6, 4.2.7). После строк версии выводятся версии CMake, yq,
  stm32-cmake или Arduino Core STM32 и, после `project()`, компилятора. Неизвестная
  версия — «версия не определена» без предупреждения.
- **`system_library: none`** (ТЗ 4.10.2) явно отключает системную библиотеку без
  предупреждения.

### Изменено

- **Язык вывода.** Без русской локали (в том числе в Docker и CI) сообщения из
  каталога выводятся на английском, например «stm32-cmake-yml version: …». Русский
  вывод — `-DSTM32_YML_LANG=ru`. Если лог разбирается скриптами, используйте коды из
  `stm32_yml_messages.jsonl`, а не текст.
- **Пример в подсказке `mcu_core`.** Ошибка для двухъядерного MCU предлагает одно
  ядро (`mcu_core: M7`), а не список `M7;M4`.
- **Неизвестное значение перечисления.** Хвост предупреждения начинается с заглавной
  буквы: «Применяется '…'» / «Значение не используется».
- **Метка `[CRC ERROR]` скрипта CRC** заменена текстами каталога: ошибка и строка
  «Сборка прервана: CRC не рассчитан.» (`SCY-E708`). Скрипты, искавшие метку в логе,
  должны проверять код в `stm32_yml_build_messages.jsonl`.
- **Сообщения на английском в русском выводе.** Строки о READONLY в скрипте
  компоновщика выводятся по-русски.

## [0.9.3] - 2026-09-27

### Добавлено

- **Артефакт `srec`.** `build_artifacts: [srec]` создаёт файл Motorola S-record
  через `stm32_generate_srec_file`.
- **Перезапуск Configure при изменении входных файлов.** Изменение YAML, IOC-файла
  или `profiles_file` перезапускает Configure при следующей сборке.
- **Предупреждение о встроенных профилях.** При заданном `profiles_file` встроенная
  секция `profiles:` по-прежнему не используется, но выводится предупреждение со
  списком её профилей.
- **Предупреждение о неприменённых размерах heap/stack.** Явно заданные
  `heap_size`/`stack_size` при скрипте stm32-cmake или явном `linker_script` не
  применяются, и Configure сообщает об этом.
- **Предупреждение о символе `_sstack`.** Если startup задаёт MSPLIM по `_sstack`
  (CubeH5 1.7.0), а скрипт компоновщика символ не определяет, Configure выводит
  предупреждение.
- **Документация.** Справочник опций `CFG-*` на русском и английском с отметками
  об изменениях 0.9.3, errata E001–E008, руководства по сценариям, исходникам,
  модулям, диагностике и режимам разработки, техническое задание
  (`docs/TECHNICAL_SPECIFICATION.md`). Навыки ИИ-агентов в `skills/` согласованы
  со справочником.
- **Тесты и CI.** Docker-окружение с закреплёнными версиями инструментов и пакетов
  STM32Cube; 139 сценариев Configure на шести парах GCC/CMake; матрица прошивок
  для STM32F103C8T6, STM32F030R8T6, STM32F411CEU6, STM32F401CCU6, STM32G431CBU6,
  STM32G474CEU6, STM32F746ZGT6 и H7/H5 с запуском в QEMU и Renode; бейджи
  результатов. Состав и команды — [Тестирование](docs/ru/testing.md).

### Изменено

- **Сбой CRC — ошибка сборки (E006).** Сбой расчёта CRC завершает сборку ошибкой
  `[CRC ERROR]`; нулевая заглушка больше не записывается. Со скриптом, который
  формирует stm32-cmake, `crc_enable: true` — ошибка Configure; отсутствие секции
  `crc_section_name` в шаблоне или явном скрипте — предупреждение.
  **Совместимость:** сборки, которые раньше завершались успешно с заглушкой
  `0x00000000`, теперь завершаются ошибкой; проекты с CRC без шаблона `.ld.in`
  или явного скрипта должны добавить его либо отключить CRC.
- **Проверка формата heap/stack.** `heap_size` и `stack_size` проверяются при каждом
  Configure: допустимы целое число байт или целое число с `K`/`M` в верхнем
  регистре. **Совместимость:** значения вроде `1k` или `0x200` при скрипте без
  шаблона раньше молча игнорировались, теперь это ошибка Configure.
- **Образ CRC и BIN из секций FLASH.** Промежуточный образ CRC и артефакт `bin`
  строятся из секций ELF с адресом загрузки в регионе `FLASH` скрипта компоновщика,
  без `objcopy --gap-fill`. Секция вне Flash (например, в резервной SRAM STM32H5)
  больше не раздувает файлы до сотен мегабайт; ограничение CRC для H5 снято. Для
  обычных проектов образ, CRC и BIN не меняются.
- **Только `profiles:` из `profiles_file`.** Остальные ключи внешнего файла больше
  не подменяют базовое значение для `_append`.
- **Неизвестные значения перечислимых ключей.** Для `toolchain_backend`,
  `system_library`, `cmsis_rtos_api`, `freertos_version`, `crc_algorithm` и элементов
  `build_artifacts` выводится предупреждение со списком известных значений и
  применяется поведение по умолчанию: для `freertos_version` — `external`, как
  фактически в 0.9.2, для `crc_algorithm` — `STM32_HW_DEFAULT` (E004). Пустые
  значения не проверяются.
- **Баннер версии.** Строки `Framework :` и `Config :` заменены на
  «stm32-cmake-yml версия: …» и «Версия в конфигурации: …». Предупреждение
  называет `stm32_cmake_yml_version` рекомендуемым параметром; справка
  «Что нового в 0.9» удалена.
- **Ранняя проверка компонентов.** Отсутствующие компоненты `hal_components` и
  `freertos_components`, а также отсутствующая обёртка CMSIS-RTOS — ошибка
  Configure с именем компонента вместо ошибки Generate.
- **Таблица портов FreeRTOS по IOC.** Добавлены C0, U0, H5, L5, U5, WL и ядра
  H7/WL; для неизвестного семейства выводится предупреждение.
- **Проверка RAM скрипта компоновщика.** Учитываются CCRAM, RAM_SHARE и ядро MCU;
  для скрипта stm32-cmake выводится «не проверялось».
- **Подсказка о `hal_conf.h`.** Называет фактический файл конфигурации HAL.

### Исправлено

- **Производные значения при смене профиля (E001).** При смене профиля в одной
  build-папке обновляются MCU и размеры heap/stack локального шаблона
  компоновщика; старые значения больше не остаются в `CMakeCache.txt`. Для явных
  переопределений используются `STM32_YML_OVERRIDE_mcu`,
  `STM32_YML_OVERRIDE_heap_size` и `STM32_YML_OVERRIDE_stack_size`.
- **Список профилей из `profiles_file` (E002).** `STM32_YML_PROFILE=list` читает
  `profiles_file` так же, как выбор профиля.
- **Ключи только из профиля (E008).** Ключи, заданные только в профиле или через
  `STM32_YML_OVERRIDE_*`, применяются без объявления в корне YAML, в том числе
  `compile_options_c`/`_cxx`, `compile_definitions_c`/`_cxx` и собственные ключи
  проекта.
- **Неполный IOC.** IOC без имени проекта, `HeapSize` или `StackSize` получает
  значения ручного режима `auto`, 512 и 1024 вместо пустых.
- **Ядро MCU.** Ядро определяется по списку stm32-cmake: у одноядерных MCU (все H7 —
  `M7`) выбирается автоматически, у двухъядерных `mcu_core` обязателен, значение
  вне списка — ошибка со списком ядер. Ядро применяется к обёртке CMSIS-RTOS и к
  размерам RAM/Flash.
- **`freertos_version: external` (E007).** FreeRTOS ищется в `FREERTOS_PATH`
  (дерево Cube или FreeRTOS-Kernel), подключаются цели `FreeRTOS::<порт>`. Если
  stm32-cmake не подключил `portasm.c` порта (`ARM_CM0` в FreeRTOS-Kernel 11),
  фреймворк добавляет его к цели порта.

## [0.9.2] - 2026-09-19

### Изменено

- **Очистка артефактов предыдущих патчей.** Удалён неиспользуемый список
  `_STM32_YML_LIST_PARAMS`, устранён продублированный заголовок парсера `.ioc`,
  документация `stm32_yml_ensure_default_value` возвращена к своей функции,
  выровнены отступы `stm32_yml_setup_system_libraries`, убрано повторное вычисление
  эталонного размера RAM, удалён фрагмент ap-патча из руководства пользователя.
- **Сравнение `system_library` в кавычках.** Параметр необязателен, и без кавычек
  CMake сравнивал имя переменной со строкой.

### Исправлено

- **Нормализация флагов с отдельным аргументом.** Токен после опции вида `--param`,
  `-include`, `-isystem`, `-Xlinker` получал ведущий дефис: запись
  `"--param max-inline-insns-single=500"` превращалась в
  `--param -max-inline-insns-single=500`, и компилятор её отвергал.
  `stm32_yml_normalize_flags` распознаёт такие опции и переносит значение без
  изменений. Флаг и значение можно записать одной строкой или двумя элементами списка.
- **Поток управления в парсере `.ioc`.** Постобработка, выбирающая версию пакета
  между `FirmwarePackage` и `CustomerFirmwarePackage`, была вложена в ветку
  `ProjectManager.LibraryCopy` внутри цикла и читала переменные, записанные через
  `PARENT_SCOPE`. Накопление переведено на локальные переменные, постобработка и
  экспорт вынесены за цикл; приоритет `CustomerFirmwarePackage` работает.
- **`_append` и замена в том же профиле.** Если профиль задавал и `X`, и `X_append`,
  дополнение приклеивалось к списку из корня YAML вместо списка профиля.
- **`-DSTM32_YML_PROFILE=list` без ключа `mcu`.** Профиль определяется по любому
  своему ключу, а не только по `mcu`; результат дедуплицируется.
- **Метка источника FreeRTOS.** В итоговой таблице параметров метка была пустой:
  переменная `_src_freertos_flag` не вычислялась.
- **Сравнение `project_name`.** Конструкция `if(${project_name} ...)` без кавычек
  ломала синтаксис CMake, если `.ioc` не содержал `ProjectManager.ProjectName`.
- **Суффикс `M` в эталонном размере RAM.** Диагностика обрабатывала только `K`, и
  `math(EXPR)` падал на значении вида `1M` (H7, F7).
- **Каталог вне дерева проекта.** `add_subdirectory` вызывался без явной бинарной
  директории, и путь вроде `../shared` давал ошибку конфигурации.
- **Бинарные директории библиотек Arduino.** Имя формировалось из последнего сегмента
  пути, и `Arduino/libraries/Cli` и `Components/Cli` совпадали. Теперь используется
  весь относительный путь; первая сборка после обновления будет полной.

## [0.9.1] - 2026-09-13

### Добавлено

- **Автоопределение размера FLASH (`flash_size: auto`).** Модуль postbuild читает
  скрипт компоновщика и определяет размер FLASH. Это вернуло внедрение CRC32 для
  backend Arduino без явного размера в конфигурации.
- **Системные библиотеки для всех backend.** `use_newlib_nano` и `system_library`
  вынесены в функцию `stm32_yml_setup_system_libraries` и работают в том числе для
  backend Arduino.

### Изменено

- **Скрипт компоновщика для Arduino.** Подключение переведено на
  `target_link_options` и свойство `LINK_DEPENDS`; зависимость от макроса
  `stm32_add_linker_script` устранена.
- **Вывод Configure для Arduino.** Убраны сообщения о поиске `ioc_file`,
  `use_cmsis`, `use_hal`, `use_freertos` и `mcu_core`.
- **Параметры CRC в логе.** `crc_section_name` и `crc_algorithm` инициализируются и
  выводятся только при `crc_enable: true`.

### Исправлено

- **Передача `use_core_main`.** Параметр `arduino.use_core_main` не доходил до ядра
  Arduino; теперь значение записывается в `CMakeCache.txt`.
- **Путь к `stm32_crc.py`.** Используется `CMAKE_CURRENT_FUNCTION_LIST_DIR`, и скрипт
  находится при любом расположении фреймворка.
- **Диагностика для Arduino.** Поиск `hal_conf.h` и проверка RAM
  (`stm32_get_memory_info`) отключены для backend Arduino: без макросов stm32-cmake
  они давали фатальную ошибку конфигурации.
- **Ложные предупреждения CRC.** Проверки Python и `objcopy` выполняются только при
  `CRC_POSSIBLE`.

## [0.9.0] - 2026-07-30

### Добавлено

- **Профили сборки (`profiles:`).** Секция `stm32_config.yml` для нескольких ревизий
  платы или MCU в одном проекте. Профиль выбирается через
  `-DSTM32_YML_PROFILE=<имя>` и перекрывает базовые значения. Для списков — замена
  (ключ без суффикса) и дополнение (суффикс `_append`). Профили можно вынести во
  внешний файл через `profiles_file:`.
- **Переопределения `-DSTM32_YML_OVERRIDE_*`.** Любой скалярный параметр можно
  перекрыть переменной кэша CMake без правки конфигурации; переопределения
  применяются поверх профиля.
- **Backend Arduino Core STM32 (`toolchain_backend: arduino`).** HAL/CMSIS через
  stm32-cmake не подключаются. Секция `arduino:` задаёт путь к ядру, стандартные и
  собственные библиотеки, вариант платы и `use_core_main`. Фреймворк создаёт
  INTERFACE-цель `Arduino::Definitions` и вызывает `add_subdirectory` для ядра и
  библиотек.
- **Параметр `linker_script_dir`.** Каталог поиска шаблона `.ld.in` и явного
  скрипта `.ld`, в корне или в профиле. Без параметра поиск идёт в корне проекта,
  как раньше.
- **Модуль `cmake/stm32_yml_profiles.cmake`.** Загрузка и применение профилей,
  семантика `_append`, переопределения, вывод списка профилей
  (`-DSTM32_YML_PROFILE=list`).
- **Модуль `cmake/stm32_yml_arduino.cmake`.** Настройка backend Arduino: проверка
  `core_path`, цель `Arduino::Definitions`, подключение ядра и библиотек.

### Изменено

- **Порядок приоритетов конфигурации.** Значения по умолчанию → `ioc_file` →
  базовый YAML → профиль → переопределения.
- **Инициализация `toolchain_backend`.** Выполняется в начале
  `stm32_yml_setup_project()` до `stm32_get_chip_info` и `add_executable`;
  дублирование `ensure_default_value` устранено.
- **Вызов `stm32_get_chip_info`.** Выполняется только для backend stm32-cmake, где
  доступен toolchain `stm32_gcc.cmake`.
- **Поиск шаблона компоновщика.** Перебор каталогов (сначала `linker_script_dir`,
  затем корень проекта) заменил три отдельных блока `if(NOT EXISTS ...)`; та же
  логика применяется к явному скрипту.
- **Сообщение о несовпадении версий.** Перечисляет нововведения 0.9 и указывает на
  обратную совместимость.
- **Версия фреймворка.** `STM32_CMAKE_YML_VERSION` — `0.9` вместо `0.8`.
  **Совместимость:** изменения 0.9 обратно совместимы; проект с
  `stm32_cmake_yml_version: "0.8"` собирается без правок, выводится информационное
  предупреждение.

## [0.8.0] - 2026-05-01

### Добавлено

- **Раздельные флаги C и C++.** Параметры `compile_options_c`,
  `compile_options_cxx`, `compile_definitions_c`, `compile_definitions_cxx`
  передаются через `$<COMPILE_LANGUAGE:C>` и `$<COMPILE_LANGUAGE:CXX>`. Общие
  `compile_options` и `compile_definitions` сохранены.
- **Нормализация флагов `stm32_yml_normalize_flags`.** Строка с пробелами
  разбивается на флаги (`"-Wall -Wextra"` → два элемента), недостающий дефис
  добавляется (`Wall` → `-Wall`), генераторные выражения `$<...>` не меняются. Для
  `compile_definitions` есть режим `NO_AUTO_DASH`.
- **Приоритет YAML над `.ioc`.** Параметры `stm32_config.yml` перекрывают значения
  из `.ioc` CubeMX без правки `.ioc`.

### Изменено

- **Поиск шаблона при `linker_script: auto`.** Три варианта имени (для
  `STM32H723VGT6`): `STM32H723VG_FLASH.ld.in` (точное совпадение),
  `STM32H723XG_FLASH.ld.in` (корпус заменён на X, как в CubeMX),
  `STM32H723XX_FLASH.ld.in` (общий вариант). Имя выходного `.ld` берётся из типа MCU
  (`H723VG`), а не из `MCU_TYPE` (`H723xx`).
- **Тип MCU для поиска шаблона.** Берётся из полного имени MCU
  (`string(SUBSTRING "${MCU}" 5 6 ...)`), а не из `stm32_get_chip_info`.
- **Проверка RAM скрипта компоновщика.** Суммируются все регионы `(xrw)` или `(rw)`
  блока `MEMORY{}`, кроме `ORIGIN = 0x00000000` (ITCMRAM); работает для H7 с
  несколькими регионами. Вместо `FATAL_ERROR` выводится сравнение с данными
  stm32-cmake.

## [0.7.1] - 2026-03-15

### Исправлено

- **`crc_enable: false` не отключал CRC.** `string(JSON GET)` возвращает булевы
  значения в верхнем регистре (`FALSE`/`TRUE`), а нормализация сравнивала со
  строчными. Нормализация добавлена при разборе JSON (`stm32_yml_utils.cmake`),
  перед `PARENT_SCOPE` (`stm32_yml_config.cmake`) и в точке использования
  (`stm32_yml_postbuild.cmake`). После обновления с затронутых версий нужна чистая
  перенастройка (удалить `build/` или `CMakeCache.txt`).
