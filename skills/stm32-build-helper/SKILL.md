# Диагностика по стадии / Phase-specific diagnostics

Справочник проверен для stm32-cmake-yml 0.9.3 (карточки 0.9.2 с отметками «Изменение в 0.9.3»). Установите фактический checkout,
версию инструментов, backend, профиль и команду, завершившуюся ошибкой. Сверьте
[reference и errata RU](../../docs/ru/index.md) / [EN](../../docs/en/index.md).
При отдельной установке навыка разрешайте docs/ относительно checkout потребителя.

## Сначала определить границу сбоя

1. Прочитайте первую содержательную ошибку и команду, а не только финальное
   сообщение Ninja. Разделите предупреждение и ненулевой код завершения.
2. Зафиксируйте source/build directories, генератор, компилятор, -D overrides,
   выбранный профиль и свежесть кэша. Не раскрывайте ненужные секреты из окружения.
3. Сопоставьте ожидаемое поведение с кодом и контрактом; если намерение неясно,
   уточните у автора до объявления дефекта или изменения поведения.
4. Исправьте подтверждённую причину минимально и повторите затронутую стадию.
   Не запускайте компиляцию или симуляцию только потому, что Configure прошёл.

[Руководство RU](../../docs/ru/troubleshooting.md) /
[English guide](../../docs/en/troubleshooting.md) содержит таблицу стадий и примеры.

## Configure и Generate

Используйте команду проекта/VS Code с его toolchain, профилем и генератором.
После изменения YAML явно запустите Configure; не полагайтесь на наличие file
watcher без проверки настроек IDE. Очистка кэша — привычный workflow автора,
но сохраните исходный лог/команду, если диагностируется повторная настройка.
Пропуск -D не удаляет override; пустой override игнорируется. Смена toolchain
требует отдельной build-папки. Не предписывайте удаление всех build-артефактов.

- Отсутствующий hal_conf: проверьте backend/use_hal, файл правильного семейства
  и include-пути основной цели. Та же формулировка от компилятора означает уже
  Compile и требует просмотра конкретной команды, а не только YAML.
- RAM-сравнение: validate_linker_script — ограниченный разбор .ld и сравнение
  с базой stm32-cmake, не проверка heap+stack, адресных пересечений или SP.
  Несовпадение не фатально; отсутствие распознанных RAM-секций предупреждает
  и пропускает проверку. Выведенное равенство после пропуска не доказывает корректность.
- Неизвестная ::-цель: проверьте её создание/ALIAS и актуальные имена зависимостей.
  Простая строка может стать внешней библиотекой, ошибка отложится до Link.
- Ошибка в FindFreeRTOS: прочитайте точную строку, аргументы, версии и нормализацию
  путей. Не объявляйте Windows-слэши универсальной причиной любой ошибки CMake.

log_target_properties выводит свойства, которые могут содержать generator
expressions. Сверяйте их с compile_commands.json для конкретного файла/языка.
verbose_build не запускает сборку и не доказывает одинаковые команды всех целей.

## Compile, Link, Post-build, Run

Эти стадии не проверены текущей конфигурационной матрицей. Разбирайте уже
предоставленные логи; запуск новой стадии определяется задачей пользователя.

Для undefined reference to Reset_Handler сначала проверьте вектор/ENTRY,
фактически подключённые startup-объекты и символы. Отсутствующий startup — одна
гипотеза, а не единственная причина. Не включайте CMSIS автоматически в bare-metal
проекте и не добавляйте вторую таблицу векторов. Startup может быть реализован
самим проектом. Для Arduino учитывайте Core/variant/wrappers.

HardFault исследуется отдельно по состоянию процессора: SP/PC, карте памяти,
векторам и доступным для данного ядра fault-регистрам. Ни лог сравнения RAM,
ни Configure success не определяют его причину. Не меняйте размеры памяти вслепую.

CRC: читайте E004/E006; успешный Configure создаёт команду, не проверяет её
результат. Нулевое CRC само по себе не доказывает ошибку. Проверка бинарного
результата и эталонного алгоритма требует отдельного сценария.

В этой работе перед подготовкой/сборкой новых прошивок уведомите автора и
дождитесь его сценариев согласно [TODO](../../TODO.md). При наличии уже данных
уточнений учитывайте их, не запрашивайте повторное разрешение без причины.

## Проверяемые основания и результат

[Manifest](../../tests/cases.json): diagnostics-toggle, diagnostics-unrecognized-ram,
diagnostics-missing-hal-conf; также missing-config, malformed-yaml, missing-linker,
hal-requires-cmsis, module-missing-target. Имена CTest начинаются с configure.
Тесты требуют конкретную диагностику и ожидаемый код завершения.

Сообщите стадию, подтверждённую причину или оставшиеся гипотезы, изменение,
выполненную проверку и её пределы. Не называйте прошивку рабочей по Configure.

## English routing

Use the English guide above. Identify the failing command and phase before
choosing a remedy. Preserve the consumer toolchain and cache context. RAM comparison
is informational; a skipped check does not validate memory. Treat missing startup,
Windows path formatting and HardFault causes as hypotheses until supported by
evidence. Configure tests do not validate linking, CRC results or execution.
